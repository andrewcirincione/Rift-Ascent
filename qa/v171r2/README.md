# Rift Ascent 1.71-r2

Canonical source: `qa/v171r2/source`. The in-game version stays 1.71; the correction is published separately as v1.71-r2, preserving the prior release.

The act splash draws a fully opaque black bar from y=198 to the screen bottom before painting its label. Art and label may fade, but scenery never shows through the bar. Every act now follows splash, character story, act relic choice, map. Both automatic splash completion and X use that route. RiftMenu starts at the story-to-relic fade's black midpoint; splash and story remain silent, including while paused. Boss dialogue retains RiftBoss continuity into combat.

A new screen value distinguishes the pre-relic story from old post-relic story saves without changing the serialized Game layout or save version. Old post-relic scenes still go directly to the map, preventing duplicate gifts. Buffered skip inputs are cleared at the relic screen so they cannot silently choose a reward.

Enemy placement compensates for transparent bottom padding and sampled rows lost during downsampling. It examines at most six bottom rows of the existing sprite, then anchors visible pixels to the battlefield floor. This corrects small hound and narrow-legged enemy gaps without moving already-grounded sprites or inventing feet for flying creatures. Player idle frame intervals drop from 36 to 24 ticks for Warden and 48 to 32 for Vesper/Proxy; enemy breathing periods shorten by roughly one third. Attack, block, power and death timelines remain unchanged.

The Tome and Armory use a split layout with a bounded full-description card, separate price and left-side lore/choices. Pause navigation uses transient selection state instead of overwriting the saved underlying selection. Up/Down selects either action; the PSP Save & Quit dispatcher is gated by that choice, and X on Resume returns to play. Main-menu help uses CHOOSE so the token parser does not insert a physical Select icon. Music gain rises from 160/256 to 184/256 (+15%), with proportional impact ducking and unchanged SFX.

Validation also checks 668 card layouts, actual rewards and payments for all characters, pause state preservation and music ducking. Validation covers all twelve character/act flows, 480 act-bar fade phases, save/pause/legacy reward safety, 1,144 enemy grounding configurations with actual visible floor pixels, resident/streamed rendering equivalence and complete artwork/media audits. The final EBOOT is exercised in PPSSPP 1.20.4, 32 MiB PSP mode, with native screenshots, live audio-buffer checks, normal and rapid-X progression, natural splash completion, grounded enemy samples, idle motion, captured fade phases and cold resume. The controller audit also verifies Up/Down focus, X Resume, Circle resume, actual event rewards, payment and visible music output. AddressSanitizer/UBSan run with leak detection disabled due the host sandbox's thread-inspection limitation.

Rebuild with `PSPDEV` set using `bash qa/v171r2/build_release.sh`. The script makes a clean PSP build, explicitly writes the version metadata, and preserves all artwork and soundtrack payloads. The hardware-confirmed loader correction and 4 MiB artwork cache are retained. Physical PSP verification of this correction remains pending.
